# Compass 9.0.0 on sdd-bench: results, 10 November 2026

This is the pre-registered measurement for ayeo-io/compass-delivery#361 [Run the pre-registered sdd-bench measurement on the 9.0.0 release candidate]. The plan is `docs/preregistration-9-0-0.md`. Compass was measured at commit `71efbb89`.

## Result

**Compass 9.0.0 fails the #361 pass rule.** It fails the token rule on all 4 scenarios, and the record rule on 3 of them. It meets the reach rule on all 4.

| Rule (#361), on every scenario | Result |
|---|---|
| Compass median tokens at most 1.5x bare | fail on 4 of 4: 3.6x to 14.2x |
| Compass reaches the target in at least bare's runs, less one | pass on 4 of 4 |
| Every Compass record passes `tools/check_record.py` | pass only on `shop-idempotency` |

The token result is not noise. On every scenario, the cheapest Compass run used more than 2 times the tokens of the most expensive bare run.

The Compass sessions make many more tool calls than bare, and most of the extra calls are `compass` commands. Every call sends the session's context again, so the tokens grow with the number of calls.

| Scenario | Bare tool calls | Compass tool calls | Of which `compass` commands |

## What the checker found

Failures, by check, over the 9 Compass records that fail:

- **test-digests** (6 runs): the digest a red or green record holds does not match the test file as it is now. The likely cause is a test file edited after it was recorded. This has not been checked.
- **land-commit** (4 runs, main issue): the manifest has no `land_commit`, or the commit that added it is not on `main`.
- **Extra issues** (5 runs): the session opened a second Compass issue for a side task, such as `untrack-compass-records` or `forget-user-test-gaps`, and did not finish it. That issue then fails `red-before-green`, `request-link`, `land-commit` or `ship-approval`.
- **ship-approval** (2 runs, main issue): approval was owed, and none is on record.
- **red-before-green** (2 runs, main issue): some scenarios have a green with no red before it.

`approvals` passed on every record.
